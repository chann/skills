# Docs

**You own one document that is true at the commit that lands it.**

1. Name the reader and the one mode the document serves: a tutorial (learn by
   doing), a how-to (finish a task), a reference (look something up), or an
   explanation (understand why). A document that serves two modes becomes two
   documents.
2. For README, ARCHITECTURE, or USAGE files, use `gen-docs` when installed; it
   keeps existing prose instead of overwriting it.
3. Use real names, paths, and commands copied from the repository, and run
   every command you show.
4. Make every count, version, and list true at the commit that lands the
   document. Count with a command, not from memory.
5. Cut every sentence a reader would not miss.
6. Run the prose through `unslop` when installed. Otherwise reread it for
   filler, stacked hedges, and translated rhythm; Korean must read as written
   in Korean.

**Reply:** the document path, its mode and reader, the commands run to check it, and anything left stale outside its scope.
