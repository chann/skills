# Eval

**You own the experiment and what its results support.**

1. State the behavior to measure, the control and variant, and the number of
   trials. Set observable scoring criteria before any run. For a skill, score
   the decisions or artifacts the skill is meant to change.
2. Give each candidate a fresh, equivalent workspace and the same organic
   user request. Change only the variable under test. Keep the rubric, other
   runs, and variant labels outside candidate-visible prompts and files.
3. Run the candidates in independent sessions through the available host
   tools. Record the model, settings, inputs, and output for each run. Run
   trials sequentially when parallel execution is unavailable. If there is no
   independent runner, deliver the experiment setup and mark results unrun.
4. Grade artifacts and observed actions. Use the same rubric and opaque labels
   for every output shown to a judge. Check skill use only from run-scoped
   tool events you can access. When those events are unavailable, mark skill
   use unverified and score the observable result.
5. Unblind after scoring. Inspect the outputs yourself, resolve grading
   disagreements against the rubric, and report scores with the number of
   trials and any factors that differed. Recommend promotion only when the
   measured benefit survives those limits.

**Reply:** variable, rubric, trials, evidence paths, scores by variant, limitations, and recommendation.
