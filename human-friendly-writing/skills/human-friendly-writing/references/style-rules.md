# 문체 규칙

용어 교체가 끝난 텍스트 전체에 적용한다. 목표는 "사람이 쓴 것 같은" 글이지
"많이 고친" 글이 아니다.

## 1. 번역투

- "~에 대하여/대해", "~를 통해", "~에 있어", "~와 관련하여" → 조사로 푼다.
  "성능에 대해 논의했다" → "성능을 논의했다"
- 이중 피동 "~되어진다", "~지게 된다" → 능동이나 단순 피동으로.
- "~에 의해" 피동문 → 주어를 앞세운 능동문으로.
- "~할 수 있다" 남발 → 사실이면 단정한다. "개선할 수 있습니다" → "개선됩니다"
- "가지고 있다" → "있다". "의존성을 가지고 있다" → "의존성이 있다"
- 추상 주어 + 만능 동사 → 사람·행동 중심으로.
  "이 구조는 이점을 제공한다" → "이렇게 짜면 테스트가 쉬워진다"
- 가벼운 동사 부풀리기 "~을 진행하다/수행하다" → 동사로 직접.
  "개선을 진행하였다" → "개선했다"

## 2. 리듬과 구조

- 비슷한 길이의 문장이 세 개 이상 이어지면 길이를 섞는다. 짧은 문장 하나가
  숨을 만든다.
- "첫째… 둘째…", "A인가, B인가" 같은 대구 공식을 지운다.
- 문단마다 같은 구조(요약문 + 부연 두 문장)가 반복되면 깬다.
- 불릿은 진짜 목록일 때만 쓴다. 흐름이 있는 내용은 산문으로 되돌린다.
- 헤딩·이모지·볼드 남용을 걷어낸다.

## 3. 어조

- 문두 접속사(그리고, 또한, 하지만)의 연속 사용을 줄인다.
- 과장 수식("완벽한", "매우 강력한")과 공치사("좋은 질문입니다")를 지운다.
- 독자가 쓰지 않는 은유·프레임워크 명칭을 독자의 말로 바꾼다
  (slop-lexicon.md 2절).

## 4. 과윤문 방지

- 이미 자연스러운 문장은 그대로 둔다. 바꿀 이유를 한 문장으로 말할 수 없으면
  바꾸지 않는다.
- 원문의 어조(반말/존대, 건조함/활기)와 글쓴이의 개성은 유지한다. 원문이 한
  글 안에서 반말과 존대를 혼용하면 더 많이 쓰인 쪽으로 통일한다.

## 5. 자기검증 체크리스트

- [ ] 수치·날짜·고유명사·코드 식별자·링크가 원문과 같은가
- [ ] 모든 문장이 원문의 내용에 대응하는가 (추가·삭제 없음)
- [ ] 보존 목록의 용어를 바꾸지 않았는가
- [ ] 소리 내어 읽었을 때 걸리는 곳이 없는가
- [ ] 바꾼 이유를 자리마다 한 문장으로 설명할 수 있는가
