# bug-hunt

[English](README.md) · [← 메인으로](../README.ko.md)

버그를 추적한 흔적을 남기면서 원인을 찾습니다. 그대로 적어 둔 재현 명령, 반증을
시도한 가설 목록, 그리고 먼저 실패한 검사로 고정한 수정입니다.

## 무엇이 다른가요?

대부분의 디버깅은 자기 기록을 잃어버립니다. 가설 세 개를 시도했다가 두 개는
조용히 접고, 수정만 남습니다. 다음 세션은 아무것도 모르는 상태로 시작해서 접었던
두 개를 다시 시도합니다.

`bug-hunt`는 그 흔적을 `.bug-hunts/<날짜>-<이름>.md`에 남깁니다. 끝나고 요약하는
게 아니라 진행하면서 씁니다. 단순한 로그와 다른 지점은 네 가지입니다.

- **확인이 아니라 반증.** 가설마다 그 가설이 틀렸음을 보여줄 관찰을 먼저 적고,
  그다음에 관찰합니다. 맞다는 근거를 찾으러 가면 언제나 찾게 됩니다.
- **범위를 넓히는 규칙.** 같은 계층에서 가설 세 개가 반증되면 다른 계층이나 다른
  전제로 넘어가야 하고, 무엇으로 옮겼는지 기록에 남깁니다. 세 번 연속 실패는
  그 자체로 정보입니다. 같은 자리에서 네 번째 가설을 만들면 그 정보를 버리는
  셈입니다.
- **반증된 가설도 남깁니다.** 지워진 줄이 아니라 남아 있는 줄이 기록의 핵심입니다.
  다음 세션이 같은 일을 반복하지 않게 막아 줍니다.
- **정리했다는 증거.** 임시로 넣은 관찰 코드에는 `BUGHUNT` 표시를 붙이므로,
  지웠다는 말이 아니라 검색으로 확인합니다.

## 설치 방법

전역 설치:

```bash
npx skills add -y -g chann/skills --skill bug-hunt
```

현재 프로젝트에 설치:

```bash
npx skills add chann/skills --skill bug-hunt
```

## 사용법

| Claude Code | Codex | 하는 일 |
|---|---|---|
| `/bug-hunt [증상 또는 실패 명령]` | `$bug-hunt [증상 또는 실패 명령]` | 재현하고, 가설을 반증하고, 수정을 검사로 고정하고, 진단 기록을 남김 |

예시:

```text
/bug-hunt /search 엔드포인트가 p50 4초야. 지난주엔 300ms였어
$bug-hunt src/rank.test.ts 가 50번에 한 번쯤 실패해
/bug-hunt 로그인 후 세션이 가끔 사라져
```

## 진행 순서

1. **증상 정리** — 관찰된 현상, 기대한 동작, 환경, 처음 본 시점.
2. **재현** — 실패하는 명령을 그대로 적고 최소한으로 줄입니다. 재현되지 않으면
   재현되지 않았다는 사실이 결론입니다.
3. **가설 목록** — 한 번에 가설 하나, 변수 하나. 추측하지 않고 관찰합니다.
4. **수정 고정** — 버그 자체 때문에 실패하는 검사를 먼저 만들고, 그다음에 통과시킵니다.
5. **정리** — `BUGHUNT` 표시가 남지 않았는지 검색으로 확인하고 프로젝트 검사를 다시 돌립니다.
6. **기록 마감** — 원인, 수정, 반증된 가설, 같은 형태가 또 있는 곳, 남은 의문.

## 하지 않는 일

- 재현하지 못한 버그를 추측으로 고치기
- 버그 때문에 실패하는 검사 없이 수정을 먼저 넣기
- 가설 세 개가 반증된 계층에서 네 번째 가설 만들기
- 기록이 깔끔해 보이도록 반증된 가설을 지우기
- 실패를 없애려고 테스트를 약화하거나 건너뛰거나 재시도로 감싸기
- `BUGHUNT` 표시를 남긴 채로 끝내기
